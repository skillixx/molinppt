# PPT AI 应用 Goal 项目拆解

本文把 AI PPT 应用拆成多个可独立验收的 Goal 项目。Goal 用于确定业务交付边界，后续每个 Goal 可以再拆成 roadmap 任务、分支和 PR。

## 拆分原则

- 一个 Goal 必须有可演示结果，不只是一组技术改造。
- 一个 Goal 尽量能独立验收，依赖关系必须清楚。
- 首版避免建设低频后台：官方模板、用户管理、用户数据管理都走代码目录、同步脚本、受控 SQL 或运维脚本。
- 首版不把视觉模型和图片生成模型作为硬依赖。
- MySQL 是业务事实来源，对象存储只保存文件内容。
- Agent 执行 Goal 时只能修改本仓库 `/home/pc-w1/ppt` 内的代码和文档；不得修改其他仓库、系统目录或外部项目的文件。

## Goal 总览

| Goal | 名称 | 业务结果 | 优先级 |
|---|---|---|---|
| G0 | 本地运行与基础环境 | 服务、数据库、对象存储、配置能稳定启动 | 必须 |
| G1 | Moling 用户入口与会话 | 用户从 Moling 进入后可识别身份并保持登录 | 必须 |
| G2 | 计费与幂等闭环 | 生成 PPT 前后能正确 reserve、settle、release | 必须 |
| G3 | 大纲与内容生成 | 用户输入主题后得到可编辑大纲和 slide 内容 | 必须 |
| G4 | 模板体系基础 | 用户能选择官方模板，模板影响生成和预览样式 | 必须 |
| G5 | PPT 资产库 | 用户生成的 PPT 可长期查看、预览、下载、删除 | 必须 |
| G6 | 导出与下载 | 用户能导出 PPTX/PDF，且只能下载自己的文件 | 必须 |
| G7 | 官方模板库工程化 | 官方模板通过 `templates/official/` 和同步脚本进入系统 | 高 |
| G8 | 用户个人模板 | 用户上传 PPT 后生成本人可用模板，限制最多 20 个 | 高 |
| G9 | 运维数据能力 | 无后台情况下可安全处理用户、配额和异常数据 | 高 |
| G10 | 上线加固 | 成本、日志、安全、并发和验收清单达到上线要求 | 必须 |
| G11 | 模型增强 | 可选接入视觉模型和图片生成模型提升效果 | 可选 |

## G0：本地运行与基础环境

目标：让项目在本地和部署环境中具备稳定运行基础。

范围：

- Node.js ESM 应用启动。
- MySQL 连接和迁移。
- MinIO/S3 兼容对象存储连接。
- `.env.example` 补齐必要变量。
- 健康检查接口可用。

不包含：

- 真实 AI 生成效果。
- 模板解析。
- 后台管理页面。

依赖：无。

验收：

- `npm start` 可启动服务。
- `npm run migrate` 可初始化数据库。
- `/api/health` 返回正常。
- 对象存储 bucket 可读写。

## G1：Moling 用户入口与会话

目标：用户从 Moling 平台进入应用后，系统能识别当前用户并建立本地会话。

范围：

- 校验 Moling launch ticket。
- 映射或创建本地 `users` 记录。
- 会话持久化。
- 当前用户查询。
- 过期会话拒绝访问。

不包含：

- 用户管理后台。
- 用户角色编辑页面。

依赖：G0。

验收：

- 用户从 Moling 入口进入后能获得有效会话。
- 服务重启后未过期会话仍可用。
- 无效 ticket 或过期会话被拒绝。
- 用户只能访问本人身份上下文。

## G2：计费与幂等闭环

目标：PPT 生成和后续增强能力都能安全接入 Moling 积分体系。

范围：

- 余额查询。
- 生成前 reserve。
- 成功 settle。
- 失败 release。
- 幂等键持久化。
- 对账 worker 或运维重试入口。
- 平台错误码到业务错误的映射。

不包含：

- 图片生成扣费策略。
- 单页编辑扣费策略。

依赖：G0、G1。

验收：

- 成功生成只扣一次积分。
- 失败任务释放预占积分。
- 同一任务重试不重复扣费。
- settle/release 失败后可重试收敛。
- 积分不足时不调用 AI 生成。

## G3：大纲与内容生成

目标：用户输入主题后，系统生成可编辑大纲，并在确认后生成结构化 slide 内容。

范围：

- 主题生成 outline。
- 大纲编辑和保存。
- 依据已确认 outline 生成 slide JSON。
- 切换模板和主题时，在不重新生成 outline 的前提下重建 deck。
- Slide JSON Schema 校验、重试和降级。

不包含：

- 复杂图片生成。
- 用户上传 PPT 解析成模板。

依赖：G2、G4 的基础 schema。

验收：

- 用户可以先生成 outline，再编辑。
- 使用已有 outline 切换模板后，页数、核心标题和要点保持稳定。
- 新模板能影响 deck 内容组织和展示样式。
- slide JSON 不合规时有重试或降级结果。

## G4：模板体系基础

目标：模板成为生成链路中的一等能力，而不是只影响前端下拉选项。

范围：

- 模板分类。
- 模板列表。
- 模板主题配置。
- layout/schema 定义。
- 预览渲染使用模板样式。
- 导出使用模板样式。

不包含：

- 官方模板后台。
- 用户个人模板解析。
- 视觉模型和图片生成模型。

依赖：G0、G3。

验收：

- 用户能按分类选择模板。
- 切换模板后预览样式变化。
- 切换模板后 PPTX/PDF 导出样式变化。
- 模板列表包含官方 active 模板和用户本人模板。

## G5：PPT 资产库

目标：用户生成的 PPT 不再只是一次性下载结果，而是可长期管理的个人资产。

范围：

- `ppt_assets` 元数据。
- 生成成功后保存资产记录。
- 用户资产列表。
- 资产详情。
- 软删除。
- 100 个 PPT 配额。

不包含：

- 用户数据管理后台。
- 跨用户资产查询页面。

依赖：G1、G3、G6 的文件索引能力。

验收：

- 用户下次进入平台能看到历史 PPT。
- 用户只能看到自己的 PPT。
- 第 100 个 PPT 可创建，第 101 个返回配额错误。
- 删除旧 PPT 后可以继续生成。

## G6：导出与下载

目标：用户可以获得可用的 PPTX/PDF 文件，并且下载链路安全。

范围：

- PPTX 导出。
- PDF 导出。
- 中文 PDF 字体和换行处理。
- 文件写入对象存储。
- `storage_objects` 文件索引。
- 短期签名 URL 或后端代理下载。
- 跨用户下载拦截。

不包含：

- 高级导出保真回归平台。
- 长期公开 URL。

依赖：G0、G1、G4。

验收：

- PPTX 可打开。
- PDF 中文不乱码。
- PDF 内容按标题和要点完整展示，不压成一行。
- 用户不能下载他人文件。
- 删除后的资产下载不可访问。

## G7：官方模板库工程化

目标：官方模板不用后台管理，直接通过代码仓库和同步脚本进入系统。

范围：

- `templates/official/{slug}/` 目录规范。
- `manifest.json` 校验。
- `source.pptx`、`thumbnail.png`、`template.json` 管理。
- 官方模板同步脚本。
- 分类种子同步脚本。
- 按 `slug` upsert MySQL。
- 模板文件上传对象存储。

不包含：

- 官方模板管理后台。
- 在线审核流程。

依赖：G0、G4。

验收：

- 新增模板目录后执行同步脚本，用户可见 active 模板。
- `manifest.status = disabled` 的模板不展示。
- 修改 manifest 后重复同步更新 MySQL，`slug` 保持稳定。
- 官方模板不占用户个人模板配额。

## G8：用户个人模板

目标：用户可上传自己的 PPT，系统生成仅本人可见的个人模板。

范围：

- 上传 PPT。
- 文件类型、大小、宏和嵌入对象校验。
- PPTX 基础结构解析。
- 提取颜色、字体、缩略图、基础布局和占位符。
- 生成个人 `template.json`。
- 20 个个人模板配额。
- 删除个人模板。

不包含：

- 完全还原复杂动画。
- 发布到公共模板市场。
- 视觉模型强依赖。

依赖：G4、G5、G6。

验收：

- 用户上传 PPT 后生成个人模板。
- 用户只能看到自己的个人模板。
- 第 20 个个人模板可创建，第 21 个返回配额错误。
- 删除 1 个个人模板后可以继续创建。
- 不配置视觉模型时基础解析仍可用。

## G9：运维数据能力

目标：在不建设后台的情况下，仍能安全处理少量用户和数据问题。

范围：

- 只读查询账号和变更账号分离。
- 用户禁用/恢复 SQL 或脚本。
- 配额重算脚本。
- 异常 PPT 资产软删除脚本。
- 异常个人模板软删除脚本。
- 对象存储清理脚本。
- 变更前备份和回滚 SQL 规范。

不包含：

- 用户管理后台。
- 用户数据管理后台。
- `/api/admin/users`、`/api/admin/ppt-assets`、`/api/admin/templates`。

依赖：G1、G5、G8。

验收：

- 可通过脚本禁用用户。
- 可通过脚本重算 `user_usage_counters`。
- 可软删除异常资产且用户不可再访问。
- 批量变更有备份、执行记录和回滚方式。

## G10：上线加固

目标：把产品从可用推进到可上线、可排查、可控成本。

范围：

- 结构化日志。
- 关键指标和告警。
- LLM 调用成本护栏。
- 单用户速率限制。
- 上传大小和 prompt 长度限制。
- 多实例并发安全。
- 安全审查。
- 验收脚本。

不包含：

- 新业务功能。
- 模型增强。

依赖：G1-G9。

验收：

- 关键链路有日志和指标。
- 超限请求被拒绝。
- 并发生成不会重复扣费或绕过配额。
- 跨用户资产、模板、下载访问被拒绝。
- 上线验收清单通过。

## G11：模型增强（可选）

目标：在基础模板体系稳定后，再用视觉模型和图片生成模型提升效果。

范围：

- 视觉模型识别上传 PPT 风格、用途和分类。
- 视觉模型辅助提取复杂版面结构。
- 图片生成模型生成封面图、插图、图标和素材变体。
- 模型失败时降级到规则解析和手工模板。

不包含：

- 首版官方模板同步依赖模型。
- 首版用户模板基础解析依赖模型。

依赖：G4、G8、G10。

验收：

- 未配置模型时基础能力正常。
- 配置视觉模型后，模板分类和版面识别质量提升。
- 配置图片生成模型后，可为指定主题生成素材。
- 模型失败不影响用户使用已有模板生成 PPT。

实现边界：

- `VISION_PROVIDER=none` 和 `IMAGE_PROVIDER=none` 是默认配置，官方模板同步和用户个人模板基础解析不依赖模型。
- 视觉模型只作为 `PersonalTemplateService` 的增强层：规则解析先产出可用 `template.json`，模型返回的分类、用途、风格、视觉和布局建议只覆盖允许字段。
- 视觉模型失败时，个人模板仍使用规则解析结果创建，并记录 `modelEnhancement.status = "failed"`。
- 图片生成通过 `POST /api/ppt/generated-images` 生成 owner-scoped 私有图片文件，支持 `cover`、`illustration`、`icon`、`variant` 四类素材。
- 未配置图片模型时图片生成接口返回 `IMAGE_PROVIDER_NOT_CONFIGURED`，不影响用户使用已有模板生成 PPT。

## 推荐执行顺序

```text
G0
  -> G1
  -> G2
  -> G4
  -> G3
  -> G6
  -> G5
  -> G7
  -> G8
  -> G9
  -> G10
  -> G11（可选）
```

说明：

- G4 要早于 G3 的完整验收，因为 slide JSON 需要模板 schema 约束。
- G6 要早于 G5 的完整验收，因为资产库必须绑定可下载文件。
- G7 可以和 G5/G6 部分并行，但上线前要接入真实 MySQL 和对象存储。
- G11 不进入首版阻塞链路。

## 首版最小闭环

首版最小闭环建议只包含：

- G0：本地运行与基础环境
- G1：Moling 用户入口与会话
- G2：计费与幂等闭环
- G3：大纲与内容生成
- G4：模板体系基础
- G5：PPT 资产库
- G6：导出与下载
- G7：官方模板库工程化
- G9：运维数据能力
- G10：上线加固

G8 用户个人模板可以作为首版增强项；G11 模型增强建议明确放到后续版本。
