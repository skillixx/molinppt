# PPT 模板扩展需求规划

## 目标

在不包含当前已经完成模板的前提下，为现有 9 个模板分类规划后续可新增的模板类型。每个分类规划 10 个新增模板，每个模板包含 3 个主题风格。

当前已排除的模板包括：

- 商业汇报：高管商务汇报、项目状态汇报
- 战略咨询：战略咨询方案
- 财务经营：财务经营复盘
- 销售方案：销售提案方案
- 产品规划：产品路线规划
- 市场营销：营销活动方案、品牌故事叙事
- 数据洞悉：数据洞察报告
- 教育培训：教育培训课件
- 融资路演：创业融资路演

后续新增模板应遵循目录结构：

```text
templates/official/<模板分类>/<模板>/<主题风格>/
```

## 数量汇总

```text
9 个分类 x 10 个新增模板 x 3 个主题风格 = 270 套主题风格
```

## 实施建议

第一阶段不建议一次性实现全部 270 套主题风格。建议先从每个分类选择 2 个高价值模板，每个模板实现 2 个主题风格。

第一阶段规模：

```text
9 个分类 x 2 个模板 x 2 个主题风格 = 36 套主题风格
```

优先选择标准：

- 使用频率高
- 商业场景明确
- 和现有模板差异明显
- 能沉淀可复用的版式组件
- 适合用代码绘制，而不是依赖整页图片

## 后续落地要求

每个新增模板都应满足：

- 有独立目录结构。
- 有唯一 `slug`。
- 有独立 `manifest.json`。
- 有独立 `template.json`。
- 有独立 `renderer.js`。
- 如果需要图片，放在当前主题目录的 `assets/` 中。
- 不直接使用整页模板图片作为背景。
- 在线预览和 PPTX 导出样式保持一致。
- 模板页面中不直接展示主题风格名称。
- 新样式应尽量拥有独立 `visual.layout`，避免复用旧模板骨架。

### 状态字段说明

| 字段 | 说明 |

| 实现状态 | `未开始`、`设计中`、`开发中`、`待同步`、`已上线`。 |
| 代码状态 | `未创建`、`目录已建`、`预览已建`、`导出已建`、`测试已补齐`。 |
| 设计思路 | 该模板应该形成的核心版式语言。 |
| 装饰图片需求 | 是否需要人物、场景、设备、产品界面、图标或纹理等局部素材。 |
| 背景类型 | 代码绘制背景方向，不允许直接使用整页截图作为背景。 |
| 优先级 | `P0` 最高，适合第一阶段先做；`P1` 次优先；`P2` 后续补充。 |

## 进度维护规则

推进模板时按以下方式更新表格：

1. 完成目录和 `manifest.json`、`template.json`、`renderer.js` 后，将代码状态改为 `目录已建`。
2. 完成 `ppt-service.js` 在线预览后，将代码状态改为 `预览已建`。
3. 完成 `ppt-exporter.js` PPTX 导出后，将代码状态改为 `导出已建`。
4. 补齐测试并通过后，将代码状态改为 `测试已补齐`。
5. 同步数据库和对象存储后，将实现状态改为 `已上线`。
6. 如果只完成设计草案，将实现状态改为 `设计中`。
7. 如果已经进入代码实现但未完成同步，将实现状态改为 `开发中`。

## 分类模板详细要求

本节用于把“模板名称 + 主题风格”进一步拆成可执行的设计要求。后续真正开发模板时，每个模板都应至少明确以下内容：

- 主题风格说明：该模板下 3 个主题分别适合什么业务语境。
- 设计思路：封面、内容页、分析页、结尾页的核心版式语言。

- 配图要求：只使用局部装饰图片、业务场景图片、产品 mockup、图标或纹理。
- 字段组合：AI 生成内容时建议包含的结构化字段，方便模板自动排版。
